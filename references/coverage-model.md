# 学员版问题覆盖：与 Interview Designer 对齐的 A–K 维度

本表只供内部检查 50 道主问题的覆盖，不显示在第一阶段的学员输出中。来源是本机 `interview-designer-1.0.0` 的 A–K 分组。该 skill 标题写“11 组 / 52 子维度”，但现有正文逐项为 83 个；以适用的 **11 组**和真实项目判断为准，不按子维度逐项凑题。

| 组 | 能力维度 | 简历出题抓手 | 学员应准备的内容 |
| --- | --- | --- | --- |
| A | 真实性与诚信 | 项目性质、本人贡献、阶段、关键数字、时间线、AI 辅助写作归属 | 明确自己做了什么、证据是什么、什么还没验证 |
| B | 问题与需求 | 用户工作流、需求来源、调研、真伪验证、立项、范围与指标 | 具体用户任务、观察依据、优先级取舍 |
| C | 方案与 AI 边界 | 为什么用 AI、规则/人工与模型分工、备选方案、选型与适用边界 | 选择理由、被放弃方案、哪种条件下不成立 |
| D | 产品形态与体验 | 入口与现有流程的关系、确认成本、无结果处理、信任与信息呈现 | 用户看到什么、怎么修改或退出、错误如何被发现 |
| E | 技术深度 | 数据来源与质量、OCR/ASR/视频切分、RAG/检索与重排、Prompt/结构化输出、模型路由、端到端链路 | 用业务任务解释选型、输入输出和本人产品职责；不把工程实现说成本人独立完成 |
| F | 可靠性与评测 | 金标准、样本与切片、指标口径、误差传递、Trace、Bad Case、回归、在线监控 | 真实错误如何发现、定位、修复、验证，及错误如何被产品承接 |
| G | 企业落地现实 | 数据维护、权限/隐私、接口、兼容、并发/延迟、配置、安全、审核疲劳、灰度回滚、模型依赖 | 落地约束、责任人、降级、成本与持续运营办法 |
| H | 商业价值 | 效率/成本/ROI、收益归因、采纳率、预算方与决策方 | 数字定义、业务意义、替代方案与收益边界 |
| I | 协作与推动 | 跨团队分工、阻力、分歧、向上沟通、非技术表达、控时 | 本人如何让他人理解和执行，有真实事件更好 |
| J | 学习与自驱 | 自我纠错、复盘、AI 工具使用、主动补缺、方法沉淀、行业判断、迁移 | 一次判断变化或学习后的具体产物与行为变化 |
| K | 岗位匹配与动机 | 职业路径、JD 对标、优势/缺口、目标级别、反问、HR 一致性 | 为什么做这类岗位，以及证据能支持到什么程度 |

## 覆盖判定

- **覆盖**：50 题中至少一道题能让学员准备该组的一个核心判断，并有真实简历锚点或明确的岗位能力要求。第一阶段只展示问题，不展示本表或维度码。
- **材料不足但适用**：仍给一道学生可准备的主问题；不要为补位编事件。后续参考回答给真实经历填充位或诚实边界。
- **N/A**：岗位或项目确实不涉及该组时才使用，并写出原因。对于 AI PM 的 A、B、C、F、G、H、I、J、K 通常不应轻易省略；D、E 应按具体项目形态安排。
- **一题多维**：内部标 1 个主维度，必要时标最多 2 个关联维度；不能把 11 个码堆到一题上制造虚假覆盖。
- **覆盖不是均分**：问题数量由候选人主张、项目成熟度与目标 JD 决定。M0–M1 更需要问企业落地判断；已有真实用户的项目更多问已经发生的采用、失败和复盘。

## 技术题深度检查

50 题里的 C/E/F/G 通常合计约 25–30 题。一个参考分布是 A3、B4、C6、D4、E10、F8、G6、H3、I2、J2、K2；这只用于发现技术覆盖不足，不要为了配额制造重复题。尤其要检查：

1. **数据与来源**：源数据质量、权威性、时效、去重、版本、权限、脱敏与维护责任；适用时包括 OCR、ASR、镜头切分或文档结构的错误。
2. **检索与知识**：数据单位/Chunk 或镜头粒度、元数据过滤、关键词/向量/图文检索、融合/重排、引用可溯源、召回相关但不可用的处理。
3. **模型与编排**：为什么用模型而非规则/人工；Prompt 输入输出契约、结构化校验、路由信号、Workflow/Agent/Tool 的动作边界、模型/知识/Prompt 版本。
4. **评测与故障**：代表性样本、Ground Truth、评审分歧、Precision/Recall 或任务成功率、线上采纳、误差沿链路传递、Bad Case Trace、回归、灰度和回滚。
5. **运行与安全**：并发、端到端延迟、缓存/重试/降级、单位成本与质量护栏、权限与隐私、Prompt Injection/知识污染、审核疲劳和人工责任。
6. **AI Coding（有相关主张时）**：可运行产物、AI 与本人贡献、正常/异常/回归测试、一次 Debug、安全检查及改变的产品判断；没有产物时只问是否做过，不能假设已完成。

技术题应问候选人在**自己项目里**为什么选择这个方案、怎样知道它有效、失败会发生在哪里。不要出脱离项目的术语默写题，也不要把学员版变成面试官现场变更情境。
