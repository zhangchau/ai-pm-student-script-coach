## 1. 第一性原理

面试官并不是在寻找“最标准的答案”，而是在估计：

`事实是否可信 × 能力是否属于本人 × 判断能否复现 × 风险是否可控 × 是否适合目标岗位`。

因此学员逐字稿必须同时准备：

- 事实和项目边界；
- 个人动作和决策权；
- 产品与技术判断；
- 产物、指标与用户证据；
- 失败、冲突和反事实；
- 商业采用与岗位迁移。
- 数据口径与归因、AI Coding 产物、带证据的行业判断和可复核的学习/自驱闭环。

## 2. 十六维能力覆盖

| 维度 | 面试官可能验证什么 | 逐字稿必须准备什么 |
| --- | --- | --- |
| 事实一致性与成熟度 | 项目性质、客户、团队、时间、M0-M7、实测或目标 | 事实台账、冲突解释、安全表述、最高成熟度证据 |
| Ownership 与产物 | 本人亲自做什么、推动什么、决定什么 | 个人边界、关键决策、PRD/原型/Workflow/Eval/Trace 走查 |
| 数据指标可信与归因 | 98% 的分子/分母、排除项、样本、周期、GT、前后对照、稳定性、归因、护栏和业务结果 | 每个关键数字一张 M15 数据卡；缺失项、实测/目标/基准/推断状态和安全表述 |
| 用户任务与 AI 必要性 | 最小价值单元、旧流程、为什么不是规则/RPA/搜索 | AS-IS/TO-BE、被改变的决策节点、MVP 与不做清单 |
| 系统与数据可信 | 端到端链路、权威来源、时效、冲突、权限、兜底 | 系统图、数据源规则、用户可见行为、责任 owner |
| 检索与文档智能 | Query、Chunk、元数据、召回、Rerank、引用支持 | 项目特有链路、选型证据、文档 Bad Case、删除节点反事实 |
| Prompt/模型/编排 | Prompt 职责、Schema、路由、Workflow/Agent/Tool 边界 | 输入输出契约、版本、模型比较、失败与人工确认 |
| Eval/Trace/发布 | 样本、金标准、Judge、严重度、Trace、回归、灰度回滚 | Eval 定义、真实样本、Bad Case Trace、发布与停止条件 |
| 延迟、成本与运行 | 端到端耗时、并发体验、单位成本、质量底线 | 产品级预算、降级策略、TCO/单笔成本、不可牺牲指标 |
| 安全与负责任 AI | 隐私、生命周期、注入/污染、供应链、公平、审计 | 权限时点、删除策略、红队案例、公平性切片、申诉机制 |
| Web/Vibe/AI Coding | 是否把产品假设变成可运行产物并验证，而非只会报工具名 | 真实产物、输入输出、AI/本人边界、测试、Debug、安全、部署边界和产品决策变化 |
| 用户采纳与商业落地 | HITL 是否真实、谁买单、ROI、定价、组织阻力 | 用户行为证据、buyer/budget/approver/veto、采用和运营方案 |
| 行为与协作 | 失败、冲突、被否决、向上影响、承担责任 | 四类真实故事及反面证据，不只准备成功案例 |
| AI 行业宏观判断 | 是否有带日期的证据、因果机制、用户工作流影响、目标公司含义和反证条件 | 共识趋势、非共识判断、目标公司影响三张卡；事实/推断/观点分开 |
| 自我学习与自驱 | 是否主动发现缺口/问题，形成产物、反馈、验证和行为改变 | 学习闭环、无人布置的主动项目、学错/放弃案例、AI 辅助结果的交叉验证 |
| 岗位匹配与迁移 | JD 差距、目标级别、自我认知、陌生场景 | 已验证/未验证能力、目标层级、30/60/90、迁移边界 |

完整输出必须添加：

```markdown
## 能力覆盖检查

| 维度 | 对应问题/逐字稿章节 | Core/Branch/N/A | 还缺什么证据 |
| --- | --- | --- | --- |
```

## 3. 四组技术专项

### A. 检索与文档结构

按项目适用性准备：

- Query 理解、改写、澄清和元数据过滤；
- 不同文档的 Chunk 结构、跨页表格、附件、版本和例外条款；
- BM25、Embedding、融合、Rerank、上下文组装和引用校验；
- Embedding/Reranker 的业务 Eval，而不是只引用榜单；
- 召回相关但不可用、过期、重复、越权或不支持结论时的行为。

### B. Prompt、模型与编排

- Router/Extract/Answer/Judge Prompt 的职责、输入输出、版本与回滚；
- JSON Schema、必填字段、禁止声明、引用 ID 和格式异常处理；
- 不同模型的同集比较、路由信号、量化损失和质量护栏；
- Workflow 与 Agent 的适用边界；
- Tool 的建议、确认、执行、待定和失败状态；
- 产品定义与算法/工程实现边界。

### C. Eval、Trace 与生产治理

- 代表性样本、分层抽样、Ground Truth、评审分歧；
- 开发集、回归集、盲测集，防止评测集污染；
- LLM-as-a-Judge Rubric、人工校准和禁止独立裁定的情况；
- 错误严重度、风险加权、拒答率和业务覆盖率；
- 一次完整 Bad Case Trace；
- 端到端延迟、单位成本、版本组合、灰度、停止与回滚。

### D. 安全、数据治理与负责任 AI

- 检索前权限与跨租户隔离；
- 原文、上下文、日志、反馈、向量和 Few-shot 的生命周期；
- Prompt Injection、知识污染、反馈投毒和越权工具调用；
- 模型权重、镜像、依赖、许可证与离线升级；
- 自动化偏见、用户盲目接受、告警疲劳；
- 公平性切片、解释、复核、申诉与审计。

重大 AI 项目至少从每组准备一个 Core 问题和一个证据/失败分支。确实不适用时写明 `N/A` 及原因。

## 4. 从简历主张生成问题

| 简历主张类型 | 必须生成的问题链 |
| --- | --- |
| `主导/负责` | 谁立项 → 决策权 → 本人产物 → 团队边界 → 被否决/改判案例 |
| `上线/落地/试点` | M0-M7 → 客户环境 → 真实用户 → 日志/反馈 → 验收/付费 |
| `准确率/效率/降本` | 决策目的 → 定义/单位 → 分子 → 分母/排除 → 来源 → 样本/切片 → 周期 → GT → 优化前 → 优化后/对照 → 计算稳定性 → 归因 → 护栏 → 业务结果 → 证据状态 |
| `RAG/Agent/模型路由` | 用户任务 → 端到端链路 → 选型证据 → Trace → 失败 → 约束变化 |
| `私有化/安全` | 数据边界 → 权限时点 → 更新运维 → 生命周期 → 事故与审计 |
| `团队/协调` | 真实冲突 → 各方立场 → 证据 → 决策者 → 结果 → 学习 |
| `续签/商业结果` | 买方 → 预算 → 验收 → 替代方案 → 因果证据 → 续费障碍 |
| `Web/Vibe/AI Coding/会编码` | 用户问题 → 为什么 Coding → 可运行产物 → AI/本人贡献 → 测试 → Debug → 安全 → 部署维护边界 → 产品决策变化 |
| `看好某趋势/熟悉 AI 行业` | 具体变化 → 证据/日期 → 机制 → 用户工作流 → 产品机会 → 商业/组织约束 → 目标公司动作 → 反证条件 |
| `学习快/自驱/从 0 到 1` | 主动发现缺口/问题 → 学习目标 → 刻意实践 → 可见产物 → 反馈/验证 → 行为改变 → 失败/取舍 → 下一缺口 |
| `学历/证书` | 哪项判断因此改变 → 真实应用 → 没有应用时的准确价值 |

## 5. 回答评分

### 单题 0-4 级

- **0**：回避、编造或事实冲突。
- **1**：只有概念和标准框架。
- **2**：有具体过去事件和个人动作，但证据弱。
- **3**：有产物、数据、版本、用户行为或可复现 Trace。
- **4**：有独立验证、业务结果、反面证据、清晰归因和迁移边界。

### 八项评分

每项 0-5 分：

1. 事实诚信与边界；
2. Ownership 与个人贡献；
3. 产品判断与取舍；
4. 技术系统理解与证据；
5. 数据指标可信度、归因与业务映射；
6. AI Coding 的产物、验证、安全和产品影响；
7. 用户商业结果与 AI 行业判断；
8. 学习自驱、表达反思与迁移。

若“事实诚信与边界”低于 3 分，总体不得评为优秀。

## 6. 学员逐字稿红旗

- 不同材料中的姓名、项目、客户、团队或指标不一致；
- 用“试点上线”掩盖只有 PRD/Demo；
- 把目标值、竞品值或估算写成实测结果；
- 98% 说不出分子、分母、排除项、样本、周期、基线、对照或 Ground Truth；
- 前后样本/周期/公式不可比，却把全部提升归因给本人；只报 Accuracy，不报覆盖率、风险、延迟、成本和业务结果；
- 每道回答都使用同一套三点式或 STAR；
- 技术词密集，但说不清用户任务、节点、产物和 Bad Case；
- 把“模型自报置信度”“有引用”“Delta 低”“Judge 分高”当作正确证明；
- 只说人工兜底，不准备用户盲目确认和告警疲劳；
- 所有故事都成功，没有失败、冲突、被否决和反面证据；
- 只会说优化 Prompt、换大模型、补知识库；
- AI Coding 只有工具名，没有可运行产物、测试、Debug、安全检查和产品决策变化；
- 行业判断只有热点口号，没有一手来源/日期、机制、目标公司含义和反证条件；
- 自驱只有课程、证书、学习时长或加班，没有主动问题、产物、反馈、验证和行为改变；
- 能说用户，却说不清买方、预算、验收和一票否决方；
- 为了显得高级，使用不符合当前年限和证据的 P7/P8 话术；
- 逐字稿像书面论文，无法在 30-90 秒内口头表达。
