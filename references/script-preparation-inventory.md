## 1. 第一性原理

逐字稿不是一组固定答案，而是一个帮助学员在压力下快速调用信息的“面试回答系统”。

一份完整逐字稿至少需要回答六件事：

1. **我是谁**：经历、定位、动机和岗位匹配；
2. **我做过什么**：项目事实、Ownership、决策和结果；
3. **我为什么这样做**：产品、技术、商业和风险判断；
4. **事情失败时怎么办**：Bad Case、冲突、责任和复盘；
5. **我能否再做一次**：迁移能力、入职计划和成长边界。
6. **我如何持续升级**：能否审计数据、用 AI Coding 快速验证、判断行业变化并主动补齐能力。

如果逐字稿只包含自我介绍、项目 STAR 和几道技术定义，它仍然是不完整的。

## 2. 使用方式

生成或诊断逐字稿时，先输出“逐字稿准备清单与缺口诊断”，不要直接开始写长篇答案。

每个维度都标记：

- `已准备`：有回答、有证据、能应对追问；
- `部分准备`：有观点或框架，但缺真实案例/证据；
- `未准备`：材料中没有；
- `N/A`：与岗位或项目确实无关，并说明原因。

优先级：

- **P0 必须准备**：多数 AI PM 面试都会使用；
- **P1 建议准备**：决定候选人深度和上限；
- **P2 定向准备**：根据公司、JD、行业和面试轮次选择。

每个重要维度至少准备：

`一句话结论 + 60 秒回答 + 真实事实/案例 + 证据 + 追问分支 + 不能说过头`。

## 3. 七层逐字稿准备维度

### 第一层：事实底座与诚信边界

| 维度 | 优先级 | 逐字稿必须准备 |
| --- | --- | --- |
| 1. 个人时间线 | P0 | 教育、公司、岗位、项目时间、空档和兼职/在读情况统一。 |
| 2. 项目性质与成熟度 | P0 | 公司项目/个人项目/课程项目；M0-M7；Demo、POC、试点、上线、验收区别。 |
| 3. 客户、团队与角色 | P0 | 客户类型、团队成员、汇报关系、投入比例、正式管理权和决策权。 |
| 4. Ownership 边界 | P0 | 亲自完成、推动他人、团队共同、算法/工程/专家负责分别是什么。 |
| 5. 指标与证据口径 | P0 | 每个数字的定义、样本、基线、金标准、归因、实测/目标/基准。 |
| 6. 不能说过头 | P0 | 待确认信息、尚未实现能力、不能展示内容、准确的安全表述。 |

### 第二层：个人定位、动机与 HR 基础

| 维度 | 优先级 | 逐字稿必须准备 |
| --- | --- | --- |
| 7. 30 秒自我介绍 | P0 | 当前定位、最强证据、目标岗位，不堆技术词。 |
| 8. 90 秒自我介绍 | P0 | 经历主线、核心项目、个人贡献、结果和边界。 |
| 9. 转行动机/职业连续性 | P0 | 为什么转 AI PM、原经验如何复用、哪些能力需重建。 |
| 10. 为什么是现在 | P1 | 能力、行业和个人选择的证据，不只说 AI 是风口。 |
| 11. 为什么这家公司/JD | P0 | 公司问题、岗位要求、本人证据、差距和可贡献内容。 |
| 12. 优势、短板与目标级别 | P0 | 被高估/低估能力、反面证据、初/中/高级判断。 |
| 13. 离职原因与稳定性 | P1 | 离开原因、选择标准、过去经历连续性、风险解释。 |
| 14. 教育/证书真实价值 | P1 | 哪个判断因此改变；若无直接应用，不把品牌当证据。 |
| 15. HR 实际问题 | P2 | 地点、入职时间、薪资期望、在读安排、竞业/保密等。 |

### 第三层：项目、用户与产品判断

| 维度 | 优先级 | 逐字稿必须准备 |
| --- | --- | --- |
| 16. 项目 3-5 分钟主线 | P0 | 用户、问题、目标、关键决策、链路、Ownership、结果、限制和复盘。 |
| 17. 用户与原工作流 | P0 | 谁使用、原来怎么做、痛点发生在哪一步、频次和损失。 |
| 18. 最小价值单元 | P1 | 一次回答/一次任务/一个决策/一个业务动作，如何映射指标。 |
| 19. AI 必要性 | P0 | 与规则、搜索、RPA、模板、人工 SOP 的比较；哪些不该用 AI。 |
| 20. 需求发现与用户研究 | P0 | 访谈/观察/数据来源、一个推翻原判断的用户发现。 |
| 21. MVP、优先级与不做清单 | P0 | 为什么先做、砍什么、资源约束、V1 不承诺什么。 |
| 22. 产品交互与人机协同 | P1 | 不确定性展示、澄清、确认、引用、拒绝、人工接管和错误恢复。 |
| 23. Roadmap 与迭代 | P1 | V1→V2、版本目标、证据门槛、什么信号调整方向。 |
| 24. 产品复盘 | P0 | 一个错误判断、如果重来改什么、现有证据如何改变决策。 |

## 4. 完整度分级

- **S0：只有简历复述**。没有问题预测、证据和追问。
- **S1：基础逐字稿**。有自我介绍、动机、项目主线和常见题。
- **S2：可面试版本**。P0 维度基本完整，有事实边界、核心技术/行为故事、M15 数据卡、AI Coding 产物或缺口计划，以及真实学习/自驱证据。
- **S3：抗压版本**。有 E3/E4 证据、Trace、指标审计、失败、商业与反事实。
- **S4：岗位定制版本**。与 JD、公司、级别和面试轮次对齐，可动态调用素材卡。

默认目标至少达到 `S2`。大厂核心岗、金融/医疗等高风险 AI、P7+ 目标应达到 `S3-S4`。

## 5. 缺口诊断模板

```markdown
## 逐字稿准备清单与缺口诊断

| 层级 | 维度 | 优先级 | 当前状态 | 已有素材/证据 | 缺少什么 | 下一步动作 |
| --- | --- | --- | --- | --- | --- | --- |
| 事实底座 | 项目成熟度 | P0 | 部分准备 | PRD、Demo | 客户使用/验收证据 | 本人确认 M0-M7 并改写口径 |
```

先列所有 P0，再列与目标 JD 相关的 P1/P2。不要用“已覆盖”掩盖只有一句观点、没有证据的情况。

## 6. 从准备维度继续细化问题

每个缺口都可以继续生成面试问题，但不要一次性无差别扩题。按下面顺序深入：

1. **主问题**：验证该维度的核心判断；
2. **事实追问**：当时具体发生了什么；
3. **证据追问**：有什么产物、数据、用户或 Trace；
4. **失败追问**：哪里出过问题、如何修复；
5. **反事实追问**：预算、时间、模型、数据或权限变化后怎么选；
6. **迁移追问**：换公司、行业或规模后哪些方法仍成立。

问题的目的不是让逐字稿越来越长，而是帮助学员找到缺失的事实、判断和证据。补齐后，应把多个问题重新收敛到同一张回答素材卡。
