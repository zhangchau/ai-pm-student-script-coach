# 学员版交付格式

严格分两阶段：第一次只交付 50 道主问题，请学员审阅；收到“可以/继续/细化”或指定题号后才展开。若用户明确说“跳过审阅，直接全量生成”，可以连续完成两阶段。第二阶段沿用已确认的题号与题干；篇幅过长可分文件，文件名写明批次题号。

## 第一阶段：只给 50 道主问题

```markdown
Q01. ……？
Q02. ……？
……
Q50. ……？

你先看这 50 道主问题，方向和深度是否合适？确认后我再按题号分批细化“考什么、回答模型、参考回答”。
```

- 题目列表中每行只有题号和主问题；不写维度码、考察焦点、优先级、简历锚点、答案或覆盖诊断。
- 内部核对 A–K 与技术能力覆盖、去重和题目深度；用户只看到精简的题目清单。
- 最后一行主动邀请学员确认或修改题目，再开始第二阶段。题干是学员练习用的主问题，不复制面试官现场追问树。

## 第二阶段：确认后每批细化 4–6 题

```markdown
# 某学员｜面试问题参考回答｜Q01–Q05

### Q01｜与概览完全相同的主问题

**这个问题在考什么**：……

**回答模型**：
1. ……
2. ……
3. ……

**参考回答（口头初稿）**：
“……”

**本人需确认**：仅写这题不能从材料判断的关键事实；如果没有则省略。
```

### 回答模型按题型选择

| 题型 | 可以采用的结构 | 易错点 |
| --- | --- | --- |
| 经历/贡献 | 情境 → 本人负责的动作 → 合作界面 → 实际结果与边界 | 把团队工作全说成本人完成 |
| 用户/需求 | 用户任务 → 旧流程与痛点 → 发现依据 → 为什么优先解决 | 用“用户需要”代替观察依据 |
| 产品/技术决策 | 目标 → 可选方案 → 选择依据与取舍 → 验证 → 不适用条件 | 只列技术名词或只讲最终方案 |
| 指标/商业 | 指标定义 → 基线与对照 → 采取的动作 → 结果与归因边界 | 没分母、样本、周期仍报精确提升 |
| 可靠性/落地 | 真实约束或错误 → 产品承接 → 谁负责 → 怎样检验与持续维护 | 把“人工兜底”当成完整方案 |
| 协作/学习 | 一次真实事件 → 本人行动或改判 → 可见变化 → 下次怎样做 | 编造冲突、失败或“自学”经历 |
| 动机/迁移 | 职业主线 → 已证明的可迁移能力 → 岗位要求 → 尚需补的能力 | 没有 JD 却硬讲某公司契合度 |

这些是表达思路，不是必须照抄的固定模板。同一批题的模型应根据题目变化。

## 参考回答的可用性检查

- 能在约 60 秒内自然讲完，并含一个具体业务场景或本人动作。
- 学员能指出每句事实来自简历、PRD、原始材料还是其本人补充；无法确认的关键点明确标注。
- 不把“参考回答”写成面试官答案要点、评分标准或演戏台词。
- 题目概览和展开批次使用同一 Q 编号、同一主问题，不改题。
