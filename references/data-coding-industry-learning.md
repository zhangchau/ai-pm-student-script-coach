## 1. 怎么使用

从简历、PRD 和现有逐字稿中圈出四类词：

- 所有数字：准确率、召回率、效率、成本、满意度、用户量等；
- 所有 Coding 主张：Web 原型、Vibe Coding、AI Coding、脚本、Demo、自动化；
- 所有行业判断：趋势、机会、模型能力、Agent、商业化、目标公司；
- 所有学习/自驱主张：自学、快速学习、主动推进、从 0 到 1。

每个主张各做一张卡。材料没有事实就写 `[待补证据]`，不要让 AI 帮你编项目。

## 2. 数据指标卡：把 98% 讲清楚

面试官看到 `准确率 98%`，脑中会问：`98 个什么 ÷ 多少个什么`。如果你只能重复 98%，这个数字反而会降低可信度。

### M15 数据卡

```markdown
#### 指标卡：指标名称
- 这个指标用于决定什么：
- 定义与统计单位：答案/字段/文档/会话/任务/用户？
- 分子：
- 分母与排除项：拒答、空结果、异常、人工接管是否计入？
- 数据来源与埋点：
- 样本量、抽样和关键切片：
- 统计周期、测了几轮：
- Ground Truth/正确标准、标注人与分歧处理：
- 优化前基线：
- 优化后/对照方式：同集、盲测、A/B 还是前后对比？
- 计算、阈值、波动/稳定性：
- 同期变化与归因：
- 护栏：Precision/Recall、覆盖率、拒答率、风险、延迟、成本、满意度：
- 业务结果：任务完成、采用、收入、降本或风险有什么变化？
- 状态与证据：实测/目标/外部基准/推断；报表、Eval、日志或验收：
- 面试时最多可以说到：
```

数据不完整时，不要硬说“提升到 98%”。可改为：“98% 是当前小样本离线测试结果，分母为 X，尚未经过线上完整周期验证，因此我把它定义为阶段性验证，不等同于业务上线效果。”其中 X 必须由本人核实，不能虚构。

必须额外准备：

- 一个总体指标很好但某个切片很差的例子；
- 一个指标提升但代价变差的取舍；
- 一个无法明确归因、因此降低表述强度的数字；
- 优化前后同口径对照或说明为什么无法对照。

## 3. AI Coding 产物卡：证明你真的做过

Web/Vibe/AI Coding 不是在简历上写工具名，而是用代码把产品假设变成可运行、可测试的产物。可以是 Web 原型、数据处理脚本、Eval 工具、自动化流程或 AI Demo。

```markdown
#### AI Coding 产物卡：产物名称
- 用户问题/产品假设：
- 为什么用 Coding，不用 Figma/无代码/人工：
- 可展示证据：页面、截图、Demo、仓库、Commit、部署地址：
- 输入 → 状态/数据/接口 → AI 能力 → 输出 → 埋点：
- AI 生成了什么；我亲自定义、修改和决策了什么：
- 正常、异常、边界和回归测试：
- 一个 Bug：如何复现、定位、修复和防回归：
- 安全检查：密钥、用户数据、鉴权、依赖、XSS/注入、许可证：
- 部署、监控、回滚和交接边界：
- 缩短了哪个验证周期，获得什么反馈，改变什么产品决策：
- 我不能声称的工程能力：
```

最低要求不是代码复杂，而是能展示“可运行产物 + 验证过程 + 产品结论”。不要把 AI 生成代码说成本人独立开发，也不要把一次性 Demo 说成生产系统。

## 4. 行业判断卡：从热点走到产品动作

至少准备三张：

1. **共识趋势卡**：大家都在讨论，但你能讲清机制和边界；
2. **非共识判断卡**：你不同意什么、证据是什么；
3. **目标公司影响卡**：这家公司应该做/不做/先验证什么。

```markdown
#### 行业判断卡：判断标题
- 观察到的具体变化：
- 证据、来源和日期：
- 事实 / 推断 / 个人判断分别是什么：
- 变化机制：能力、成本、交互、数据、组织或监管：
- 影响哪个用户的哪个工作流；不适合谁：
- 最小产品机会与验证方式：
- 商业、部署、数据、安全和采用约束：
- 对目标公司的 Build/Buy/Partner、优先级和壁垒影响：
- 入职后 30/60/90 天如何验证：
- 什么证据会推翻或修正这个观点：
```

涉及“现在”“最新”“行业目前”等事实时，面试前用官方/一手来源核对并写日期。不要背无来源的市场规模和模型榜单。

## 5. 学习与自驱卡：证明你能持续成长

至少准备两张：一张“主动学习闭环”，一张“无人布置但主动发现并推动的问题”。最好再准备一次学错、放弃或被纠正的经历。

```markdown
#### 学习/自驱卡：主题
- 哪个真实任务让我发现能力缺口：
- 无人要求时，我为什么仍决定推进：
- 学习目标和完成标准：
- 资源选择及可靠性判断：
- 刻意实践/实验，不只是看课：
- 可展示产物：PRD、Demo、Eval、代码、笔记、分享或流程：
- 谁/什么给出反馈；AI 助手的答案如何交叉验证：
- 遇到的失败、放弃或方向调整：
- 后续哪项行为、判断或结果发生变化：
- 持续节奏、取舍方法和下一缺口：
```

不要用“我每天学两小时”“我拿了证书”“我经常加班”代替自驱证据。面试官要看的是主动发现问题、形成产物、接受反馈、改变行为。

## 6. 最低完成标准

- 每个简历关键数字都有一张 M15 数据卡；缺信息的字段明确 `[待补证据]`；
- 至少一张 AI Coding 产物卡；没有真实产物就把它列为下一步练习，不编造；
- 三张行业判断卡，至少一张落到目标公司，且证据带日期；
- 两张学习/自驱卡，至少包含一项可展示产物、一次反馈和一次行为改变；
- 每张卡都能讲 15 秒结论、60 秒主回答，并能应对证据、失败、反事实和迁移追问；
- 目标值、外部基准、离线小样本和线上实测没有混用。
